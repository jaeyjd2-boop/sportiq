# SportIQ 개인정보 요청 관리자 처리 절차 (스테이징)

상태: 운영 준비 문서. 실제 요청 접수 E2E 검증 및 개인정보처리방침 확정 전에는 정식 운영 절차로 공표하지 않는다.

## 1. 요청 확인
- WordPress 관리자에서 **SportIQ 개인정보 요청** 메뉴 확인.
- 요청 종류: access(열람), export(내보내기), erase(삭제 요청).
- 요청 기록의 작성자 ID와 메타 `_sportiq_request_user_id`가 일치하는지 확인.
- 접수 번호, 접수 일시, 종류, 처리 담당자, 처리 상태를 내부적으로 기록한다.
- 플러그인 0.1.0은 이메일 통지 및 자동 처리 기능을 제공하지 않으므로 관리자가 직접 정기 점검한다.

## 2. 본인 확인
- WordPress 로그인 세션을 통해 접수되더라도 추가적인 본인 확인 절차를 운영 정책에 따라 결정한다.
- 비밀번호, 이메일 인증 링크, 재설정 토큰을 이메일이나 채팅으로 요청하지 않는다.
- 타인 계정에 관한 요청이나 소유 관계가 불분명한 요청은 처리하지 않고 확인 절차를 거친다.

## 3. 열람 및 내보내기
- WordPress 기본 개인정보 내보내기 기능의 적용 범위를 확인한다.
- `sportiq_favorites_v1` 사용자 메타가 기본 내보내기에 포함되는지 **실제 테스트로 검증**한다.
- 누락된다면 SportIQ 전용 exporter 구현 후 재시험한다.
- 민감 정보가 포함된 파일은 본인 확인 및 안전한 전달 절차를 거친다.

## 4. 삭제 요청
- 삭제 요청 접수는 삭제 완료를 의미하지 않는다.
- WordPress 계정 및 `sportiq_favorites_v1` 사용자 메타를 포함한 삭제 범위를 사전 확인한다.
- 법적 보존 의무 및 삭제 예외가 있는지 검토한다.
- 승인 전에는 사용자 계정 또는 데이터를 자동 삭제하지 않는다.
- 스테이징의 전용 테스트 계정으로만 삭제 절차를 검증하고, 처리 후 계정·관심 목록이 남아 있지 않은지 확인한다.
- 백업·로그 등 별도 보관 데이터에 대한 처리 및 보존 기준도 검토한다.

## 5. 완료 기록 및 통지
- 처리 일시, 담당자, 조치 범위, 검증 결과, 예외 사항을 기록한다.
- 공식 문의 이메일이 확정되면 회원에게 접수 및 처리 결과를 안내하는 절차를 마련한다.
- 현 플러그인의 `_sportiq_request_status` 값은 접수 시 pending으로 기록될 뿐, 관리자 상태 변경 UI는 구현되어 있지 않다. 수동으로 처리 상태가 바뀐다고 가정하지 않는다.

## 6. 출시 전 차단 조건
- 회원 A/B 데이터 분리 테스트: 미실시
- 비밀번호 재설정 테스트: 미실시
- 개인정보 요청 접수 및 관리자 조회 테스트: 미실시
- exporter/eraser 통합 및 삭제 테스트: 미구현 또는 미검증
- 회사 법적 상호, 문의처, 보유 기간 등 개인정보처리방침: 미확정
- 개인정보 요청 페이지 ID 52: 비공개 초안 유지

운영 주의: 관리자 화면의 요청 기록에는 계정 식별자가 포함된다. 접근 권한은 최소화하고, 필요 이상의 개인정보를 요청 기록에 저장하지 않는다.
